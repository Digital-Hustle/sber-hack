# rules.md — правила для людей и агентов (кейс «Документы»)

> Каждое правило защищает от снятия с конкурса или от потери баллов. В скобках — ссылки на критерии положения (Д = допуск, СН = снятие, Б = бонус).

## 1. Красные линии (нарушение = снятие)
1. **Вся проверка входящего — на сервере** (Д2). Размер, тип по сигнатуре (magic bytes), целостность, шифрование PDF, число страниц, разрешение, дубликаты — проверяет `intake`. Проверки во фронте — только подсказка до отправки, сервер всё равно проверяет заново.
2. **Разбор только из содержимого файла и только моделью** (Д5, СН). Тип и поля определяются по тексту/изображению документа: OCR/текстовый слой → `LlmGateway` → схема поля → детерминированная проверка. Имя файла, расширение, порядок загрузки и «пункт», куда положил соискатель, в классификатор не передаются (`guard.sh` ловит `originalFilename` в docproc/ocr). Регулярные выражения и контрольные суммы **проверяют и нормализуют** ответ модели, но не заменяют её.
3. **Никакой подгонки под тестовые файлы** (СН). Нельзя: имена/хэши файлов открытого набора в коде и промптах, правила «если в тексте есть фамилия Иванов», few-shot примеры из открытого набора. Можно: синтетические примеры (`eval/synthetic/`), общие признаки вида документа из `docs/DOC-TYPES.md`. Открытый набор лежит вне git и используется только для замера (`docs/EVAL.md`).
4. **Приём мгновенный, разбор в фоне, работа не теряется** (Д7, СН). `POST` файла отвечает `202` за доли секунды со статусом `RECEIVED`. Разбор — только из очереди `jobs` в PostgreSQL (lease + `FOR UPDATE SKIP LOCKED`), стадии сохраняются в БД. Рестарт любого сервиса посреди разбора → задание подхватывается заново. Нельзя: обрабатывать в обработчике запроса, `@Async`/потоки без записи в БД, очередь только в Kafka или в памяти.
5. **Статус «готово» — только после реального ответа модели** (СН). Модель недоступна → стадия `WAITING_MODEL` с понятной причиной и автоповтором, а не `DONE`. Никаких заготовленных ответов, «пустых полей = успех», даже как запасной вариант.
6. **Только PostgreSQL** (Д4, СН). Файлы — в Postgres (`bytea`, зашифрованы AES-256-GCM), Keycloak — тоже в PostgreSQL. Никаких `Map` в памяти как хранилища, H2/SQLite, файлов рядом с кодом, «только в очереди».
7. **Данные людей — только после входа** (Д8, СН). Каждый эндпоинт оператора и каждый файл проверяют JWT и роль на сервере; прямая ссылка без входа → 401. Соискатель видит только свою заявку по ключу заявки (хэш в БД), без перечисления чужих id. Форма входа без проверки на сервере = снятие.
8. **Рабочее место оператора показывает только реальные заявки** (СН). Никаких захардкоженных карточек и цифр очереди; демо-заявки — только через тот же API приёма с пометкой `source=DEMO`.
9. **Модель — только через `LlmGateway` в `libs/llm`** (Д6). SDK и URL провайдеров — только там (ArchUnit + `guard.sh`). Провайдер выбирается `LLM_PROVIDER`, локальный Ollama обязан работать без интернета.
10. **Никаких секретов в git** (Д9, СН). Только `infra/.env` (в `.gitignore`), в репо — `.env.example`. Реальные документы людей и открытый набор организаторов в git тоже не кладём (ПДн).
11. **Каждый понимает свой код** (Д12, СН). Не мержим код, который владелец не объяснит за 60 секунд.
12. **Без вирусных лицензий** (п. 5.8.4). Запрещены GPL/AGPL/SSPL: **PyMuPDF/fitz (AGPL), pdf2image + poppler (GPL), ghostscript (AGPL), iText (AGPL), MinIO (AGPL)**. PDF — `pypdfium2` (Apache-2.0/BSD) и `pdfplumber` (MIT), OCR — Tesseract (Apache-2.0), выгрузки — Apache POI / PDFBox (Apache-2.0). Новая зависимость = строка в `docs/DECISIONS.md` с лицензией. Веса моделей — только с разрешающей лицензией (Qwen2.5-VL-3B — research-лицензия, нельзя).
13. **Код пишется только на хакатоне** (п. 7.3). До старта — документы, правила, скрипты, CI.

## 2. Архитектура (как в «Проходной», ADR-001)
- Сервисы в `services/<name>/`, общие библиотеки `libs/common` (инфраструктура) и `libs/llm` (слой модели). Бизнес-логики в libs нет.
- `intake` владеет заявками и файлами, `docproc` — заданиями и результатами разбора, `review` — работой оператора и историей. Чужую БД не читаем: `/internal/**` или события.
- Публикация событий — только через outbox, потребители идемпотентны по `eventId`, топик `<владелец>.<агрегат>.v<N>`.
- Синхронные вызовы — только docproc → intake (файл) и docproc → ocr (текст), с таймаутом и circuit breaker. Ошибка = повтор задания, не потеря и не «готово».
- Время только через `Clock`. Деньги/даты — типами, не строками.

## 3. Backend-конвенции (Java, Python)
- Полные правила — скилл `../.agents/skills/backend-spring/SKILL.md`. Java 21, Spring Boot 3.5, Gradle Kotlin DSL, версии только в `services/gradle/libs.versions.toml`.
- Пакеты `ru.documents.<svc>`: `api/controller` (+`impl`), `api/dto/request/*Rq`, `api/dto/response/*Rs`, `features/<f>/{command,query,application,api,spi,gateway}`. ArchUnit + `be-check.mjs`.
- jOOQ + Liquibase, миграции только `scripts/new-migration.sh <svc> <slug>`. Смерженный changeset не редактируем.
- Ошибки — RFC 7807 `application/problem+json` с `code` из API.md, `detail` по-русски и `hint`.
- Обязательные тесты: проверки приёма (по тесту на каждый код), дубликаты, очередь (рестарт посреди задания, гонка двух воркеров за одно задание), валидаторы полей (MRZ, СНИЛС, ИНН, даты), поведение при сбое модели, матрица «эндпоинт × роль» + IDOR, прогон `eval/` в CI на синтетике.
- Python (ocr): `uv`, `ruff`, `mypy --strict`, `pytest`; FastAPI, pydantic `*Rq/*Rs`, ошибки — `application/problem+json`.
- Логи в JSON с `traceId`. Текст документов, поля и файлы (ПДн) в логи не пишем — только id и коды.

## 4. Frontend-конвенции
- Полные правила — скилл `../.agents/skills/frontend-fsd/SKILL.md`; дизайн — `frontend/docs/DESIGN.md` (токены, ADR-033 «Проходной» действует и здесь).
- Одно приложение Vite + React 19 + TS strict, FSD, зоны `/apply` (соискатель, mobile-first) и `/operator` (desktop, роли через Keycloak).
- Типы API — из `contracts/openapi/*.json` (`npm run gen:api`). Ручной `fetch` запрещён. Токены — в памяти; ключ заявки соискателя — в URL-фрагменте ссылки возврата и в памяти, не в localStorage.
- У каждого экрана четыре состояния: загрузка, пусто, ошибка («Повторить»), данные; отдельно — потеря сети. Статус каждого файла видно сразу и без перезагрузки (SSE).
- Каждый код отказа и непригодности имеет человеческий текст и «что сделать» («Переснимите при дневном свете, весь разворот в кадре»).

## 5. Git
- Trunk-based: короткие ветки `feat/DP-03-job-queue`, мерж в `main` только через PR по зелёному CI. Conventional Commits со ссылкой на ID: `feat(docproc): FR-20 очередь заданий с lease`.
- Коммитит человек, который работал с агентом, под своим именем (история — часть оценки, Д9).
- Никаких `node_modules`, `build/`, `.venv/`, `.env`, моделей, сканов и документов в git.
- Каждые 2 часа — тег `docs-demo-N` (стабильная точка для отката).

## 5.1 Работа агентов через PR
Цикл и скрипты — скилл `documents-dev`: ID → ветка → `scripts/verify.sh` + `scripts/guard.sh` → `scripts/open-pr.sh`. Агент не апрувит свои PR. Мерж — человек-владелец после зелёного CI или агент по явному делегированию (`docs/MEMORY.md §3`). После clone: `scripts/install-hooks.sh`.

## 6. Definition of Done
- [ ] Требование FR/NFR закрыто, ID в коммите
- [ ] Работает через интерфейс (Д3), а не только через curl
- [ ] Ошибки внятные, коды из API.md
- [ ] Состояние в БД, переживает рестарт; разбор — в фоне
- [ ] Тест или шаг в `scripts/smoke.sh`; для разбора — `eval/` не хуже, чем было
- [ ] Владелец может объяснить код
- [ ] Документация/ADR обновлены

## 7. Как понимать запросы людей (для агентов)
- Слова участника — мысль, которую надо понять, а не точная спецификация. Восстанови цель, сверь с документами, сделай то, что лучше её достигает.
- Противоречит документам или красным линиям — скажи и предложи вариант. Неоднозначно и дорого ошибиться — один уточняющий вопрос.
- Не цитируй людей дословно в коде, интерфейсе, коммитах, PR и документах.
