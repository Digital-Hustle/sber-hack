# PRD — review

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот модуль.

## Обзор
Бэкенд рабочего места оператора: проекция заявок и документов из событий, очередь с приоритетами, карточка заявки (поля с уверенностью и проверками), правки полей и типа, подтверждение и решение, запрос «дослать/переснять», история (append-only), сверка ФИО/дат/номеров между документами, истекающие документы, карточка для кадров, метрики очереди.

## Проблемы
- Оператор должен за минуту сверить заявку: видеть оригинал рядом с полями и сразу понимать, что перепроверить.
- Правки оператора не должны теряться и должны быть видны в истории (кто/когда/что).
- На пустой БД нельзя показывать «красивые» цифры.

## Цели
1. Карточка: оригинал + поля + уверенность + проверки + расхождения между документами.
2. Каждое действие → `application_history` (append-only, триггер запрета UPDATE/DELETE).
3. Метрики очереди считаются из реальных событий (`stage_events`, `decisions`).
4. Доступ по ролям и маскирование ПДн для `AUDITOR` (B-07).

## Пользователи
- Оператор (`OPERATOR`), старший оператор (`SENIOR_OPERATOR`: решения, переразбор, отчёты), аудитор (`AUDITOR`: только история и метрики, ПДн замаскированы).

## Ключевые функции
- Очередь: статусы, ожидание, «есть что перепроверить», фильтры, курсоры; «взять следующую» (назначение с блокировкой).
- Карточка: результат из docproc, правки поверх (`field_overrides`), итоговое значение = правка ?? модель.
- Действия: исправить поле/тип, подтвердить документ, запросить дозагрузку, «разобрать заново», решение по заявке.
- Сверка между документами (`findings`): ФИО (с транслитерацией), дата рождения, номер паспорта в патенте/уведомлении.
- Истекающие документы (`expires_within`), выгрузка XLSX; карточка соискателя DOCX/PDF для кадров.
- Метрики очереди: ждут / в разборе / у оператора / решено, время ожидания p50/p95.
- SSE `/operator/stream` — изменения очереди.
