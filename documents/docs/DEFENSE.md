## Снятие с конкурса — почему не про нас
| Основание | Почему не про нас | Проверка |
|---|---|---|
| Ответы подогнаны под тестовые файлы | В коде нет имён, хэшей или содержимого тестовых файлов; тип и поля — модель по тексту + проверки кодом; eval считает метрики, ничего не настраивает (rules.md §1) | Свой документ, которого нет в наборах → поля извлечены |
| Данные только в памяти / файле рядом с кодом / только в очереди | Всё в PostgreSQL (том `pgdata`), Kafka — только доставка событий (outbox), очередь заданий тоже в PostgreSQL | `docker compose restart postgres docproc` |
| Оператор видит заготовленные данные | Пустая БД → «нет заявок» и нули в метриках; карточка собирается из событий intake/docproc | Чистый стенд → очередь пустая |
| «Готово» без обращения к модели | Стадии идут только по результату шага; без модели — `WAITING_MODEL`, не «готово» | `docker compose stop ollama` → `WAITING_MODEL`, `start` → догнал |
| Обработка в момент отправки, человек ждёт | Загрузка — запись файла + событие, `202` за десятки мс; разбор — воркеры docproc | Время ответа загрузки в DevTools |
| Работа теряется при перезапуске | Аренда задания истекает → его берёт другой воркер; выходы стадий сохранены | `attack.sh` — рестарт docproc посреди разбора |
| Данные людей доступны без входа | Соискатель — ключ заявки 256 бит (в БД только хэш), чужой ключ → 404; оператор — JWT с ролью; файлы без входа → 401/404; кэш файлов запрещён | `attack.sh` T1/T2/T10 |
| Секреты в репозитории | `gen-env.sh` генерирует `.env` (в `.gitignore`); gitleaks в CI | `git log -p | gitleaks` |
| Команда не может объяснить решение | Этот файл, DEMO.md, AGENTS.md модулей | — |

## 60 секунд о модуле
- **gateway** — единственный вход за Caddy. Проверяет JWT оператора (`iss`, `aud=documents-api`) или пропускает ключ соискателя дальше; `/internal/**` → 404; лимиты размера тела по маршрутам; лимит частоты (создание заявки, код возобновления, загрузки) → 429 + `Retry-After`; CORS только свой origin.
- **intake** — заявки и файлы. Анкета → `RequirementsEngine` по правилам из таблицы `doc_requirements` строит набор документов. Загрузка: `FileInspector` (сигнатура, размер, читаемость, пароль), точный дубль по `sha256`, почти-дубль по perceptual hash, AES-256-GCM, outbox `DocumentReceived`, ответ `202`. Принимает стадии от docproc и переносит документ в нужный пункт по определённому виду; делит многостраничный файл по сегментам (FR-07).
- **docproc** — фоновый разбор. Воркеры берут задания из `jobs` (`SKIP LOCKED`, аренда), шаги: текст (ocr) → вид (модель) → поля (модель, JSON Schema вида) → проверки (даты, MRZ, контрольные суммы СНИЛС/ИНН, форматы) → уверенность поля (`ConfidenceScorer`, MATH.md) → итог `PARSED` / `NEEDS_REVIEW` / `UNREADABLE`. Сбой модели — повторы и `WAITING_MODEL`, без траты попыток.
- **ocr** (Python) — предобработка снимка (поворот, выравнивание, контраст), Tesseract `rus+eng` со словами и координатами, PDF-текстовый слой как есть, поиск MRZ, оценка качества (размыто, темно, обрезано).
- **libs/llm** — `LlmGateway` (`structured`, `vision`, `status`), адаптеры Ollama / OpenAI-совместимый / GigaChat, ограничение одновременных вызовов, таймауты, журнал вызовов и метрики. SDK провайдеров нигде больше не импортируются (ArchUnit).
- **review** — рабочее место оператора: очередь (назначение, «следующая»), карточка (скан + поля, подсветка места поля), правка полей и вида, подтверждение, запрос «дослать», решение; сверка между документами (`CrossChecker`: ФИО с транслитерацией, дата рождения, номер паспорта), истекающие документы, история (append-only), выгрузки DOCX/XLSX/PDF, метрики очереди.
- **frontend** — `/apply`: согласие, анкета, чек-лист «что нужно», загрузка (камера, несколько файлов), стадии по SSE, понятные причины и «переснять»; `/operator`: очередь, карточка с горячими клавишами, история, отчёты, роли.

## Вопросы судей → ответ
| Вопрос | Ответ | Показать |
|---|---|---|
| Где проверяется файл, что если обойти фронт? | Только на сервере: intake `FileInspector` + `UploadService`; фронт ничего не решает. Обход фронта даёт те же коды | `curl -F file=@noise.pdf …` → 415 `FILE_TYPE_UNSUPPORTED` |
| Как определяете тип? А если переименовать файл? | Имя файла и пункт в модель не передаются (`ClassifyStage`); вид — по тексту + признакам (MRZ, форматы номеров); тип файла — по сигнатуре | `passport.jpg` → `x.pdf` → тот же вид (attack.sh) |
| Что если модель не уверена? | Уверенность ниже `CLASSIFY_MIN_CONFIDENCE` или `UNKNOWN` → `NEEDS_REVIEW` с причиной `TYPE_UNKNOWN`, оператор выбирает вид; ничего не придумываем | Карточка с «вид не определён» |
| Откуда уверенность поля и порог? | Свёртка: самооценка модели, найден ли фрагмент-источник в тексте, OCR-уверенность слов, прошли ли проверки; порог τ = `FIELD_REVIEW_THRESHOLD` — поля ниже идут оператору первыми | MATH.md |
| Что при рестарте посреди разбора? | Выход каждой стадии в БД, аренда задания истекает → продолжаем со следующей стадии; повторы идемпотентны | `docker compose restart docproc` |
| Что при падении модели? | Таймаут → 2 повтора с паузой → `WAITING_MODEL` (видно соискателю и оператору); воркер пробует снова, попытки не тратятся; после восстановления догоняет сам | `docker compose stop ollama` |
| Непригодный файл? | OCR оценивает качество; мало текста / размыто / темно / обрезано → `UNREADABLE` с причиной и подсказкой, ни одного поля «наугад» | Размытое фото → «Снимок размыт» |
| Не подогнано ли под тестовые файлы? | В коде нет ничего про конкретные файлы; eval только меряет; набор синтетики генерируется скриптом `gen_synthetic.py` | `rg syn-0 services/` → пусто |
| Почему такая локальная модель? | Замер на CPU (LLM.md, таблица): точность типа и полей, время на документ, RAM; лицензии Apache-2.0 | LLM.md, артефакт `documents-llm-bench` |
| Как переключить провайдера? | `LLM_PROVIDER=ollama|openai|gigachat` в `.env`, `docker compose up -d docproc`; код не меняется | `GET /docproc/api/v1/model/status` + бейдж у оператора |
| Кто видит сканы, что с ПДн? | Файлы зашифрованы, отдаются только через intake с проверкой ключа/роли и записью в журнал доступа; аудитор видит маски; тексты и поля не логируются | SECURITY.md, `file_access_log` |
| Как оператор экономит время? | Сомнительные поля сверху, подсветка места на скане, J/K/E/Enter, «следующая заявка», автоматически подтверждённые поля, счётчик «сэкономлено, мин» | Карточка |
| Многостраничный PDF с несколькими документами? | Модель размечает страницы, код проверяет; основной документ — его страницы, остальные intake выделяет в отдельные пункты, каждый разбирается по своим страницам | DEMO.md, шаг 4а |
| Масштабирование? | docproc — сколько угодно экземпляров (очередь в БД); intake/review — один экземпляр из-за SSE в памяти (дальше — Redis/Kafka pub-sub); M/M/c в MATH.md | MATH.md |
| Что смотрите в эксплуатации? | Prometheus (профиль `observability`) + правила: сервис не отвечает, ждём модель > 5 мин, очередь растёт, ошибки модели; Jaeger — трейс документа целиком | ARCHITECTURE «Наблюдаемость» |
