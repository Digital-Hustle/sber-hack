# Оценка качества разбора — честно и без подгонки

Блок «Качество разбора» (30 баллов) судьи считают **на закрытом наборе**, которого у нас нет. Значит, единственная выигрышная стратегия — обобщение, а не запоминание открытого набора. Здесь — как мы меряем и как не скатиться в подгонку (снятие).

## Наборы
| Набор | Где лежит | Для чего |
|---|---|---|
| Открытый (от организаторов) | **вне git**: `~/datasets/documents-open/` у B2 и на сервере, путь в `EVAL_OPEN_DIR` | замер, разбор ошибок по категориям |
| Синтетический | `eval/synthetic/` в git (сгенерированные, без реальных людей) | CI, регресс, few-shot |
| Свой «закрытый» | вне git: документы членов команды с согласия, переснятые фото | имитация закрытого набора: отличия в ракурсе, свете, качестве |

Разметка: `eval/labels/<set>.jsonl` — `{file, type, fields: {name: value}}`; для открытого набора разметка тоже вне git, если содержит ПДн.

## Метрики (`eval/run.py` → `eval/reports/<date>.md`)
- **Тип**: accuracy, матрица ошибок, доля `UNKNOWN`/`NEEDS_REVIEW` (честная неуверенность лучше неправильного ответа).
- **Поля**: по каждому полю exact match после нормализации, precision (сколько заполненных верны), recall (сколько из размеченных заполнено), отдельно — «выдумано» (заполнено, а в документе нет).
- **Непригодные**: доля верно отбракованных и ложных отказов.
- **Время**: p50/p95 на документ по стадиям; провайдер и модель.
- **Калибровка уверенности**: точность в корзинах уверенности (0.9+ должно быть ≥ 0.9 верных) — для B-02 и порога `FIELD_REVIEW_THRESHOLD`.

## Правила против подгонки (rules.md §1.3)
1. Изменение промпта/весов/порогов принимается, только если оно **не ухудшает свой «закрытый» набор** и улучшает открытый в целом, а не на одном файле.
2. Никаких условий по конкретным значениям из открытого набора (ФИО, номера, названия файлов). `guard.sh` ищет имена тестовых файлов в коде и промптах.
3. Разбор ошибок — по **категориям** (поворот, блик, рукописное, латиница, двухстраничный разворот), фиксы — общие (предобработка, промпт для категории, проверка).
4. В отчёте честно пишем, где ошибаемся.

## Как запустить
```bash
cd documents/eval
uv run python run.py --set synthetic                   # CI
EVAL_OPEN_DIR=~/datasets/documents-open uv run python run.py --set open --api https://<host>
```
`run.py` грузит файлы через **публичный API** (как соискатель), ждёт итоговую стадию и сравнивает поля оператора-API с разметкой — то есть меряем систему целиком, а не отдельную функцию.
