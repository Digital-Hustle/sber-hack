# Безопасность и ПДн — «Документы»

Половина оснований для снятия здесь — про доступ к данным людей (Д8: «по прямой ссылке без входа данные не открываются», «форма входа есть, но ничего не проверяет»). Плюс бонус B-07 (обезличивание/ограничение доступа).

## 1. Модель доступа
| Кто | Как входит | Что видит | Роли |
|---|---|---|---|
| Соискатель | ключ заявки в ссылке (256 бит, в БД `sha256`), код возврата + контакт для другого устройства | только свою заявку: стадии, причины, запросы оператора; **значения полей не показываем** | `APPLICANT` (тип аутентификации, не роль Keycloak) |
| Оператор | Keycloak SSO (OIDC Code + PKCE) | очередь, карточки, сканы назначенных заявок; номера маскированы до «показать» | `OPERATOR` |
| Старший оператор | Keycloak + **TOTP** | всё оператора + перераспределение, «разобрать заново», выгрузки | `SENIOR_OPERATOR` |
| Аудитор | Keycloak + TOTP | журнал доступа и изменений, без сканов | `AUDITOR` |
| Сервисы | Keycloak service account (client credentials), `aud=<сервис>` | только `/internal/**` своего контракта | `SVC_<SERVICE>` |

## 2. Keycloak
Realm `documents` из `infra/keycloak/realm-documents.json` (секреты — плейсхолдеры `${ENV}`), хранит данные в PostgreSQL. Клиенты: `documents-operator` (public, PKCE, redirect `https://<host>/operator/*`), `documents-api` (audience), `svc-intake`, `svc-docproc`, `svc-review` (confidential). Политики: пароль ≥ 12, brute-force detection, access token 5 мин, refresh с ротацией, SSO idle 30 мин, required action `CONFIGURE_TOTP` для `SENIOR_OPERATOR`/`AUDITOR`. Демо-пользователи создаются из `.env` (`KC_DEMO_OPERATOR_PASSWORD`).

## 3. Модель угроз → защита → проверка
| # | Угроза | Защита | Проверка |
|---|---|---|---|
| T1 | Открыть карточку/скан по прямой ссылке без входа | каждый сервис сам проверяет JWT и роль; фронт-guard — только удобство | `smoke.sh`: 401 на `/review/**`, `/files/**` |
| T2 | Перебрать id чужой заявки (IDOR) | ключ заявки привязан к одной заявке; чужой id → 404; UUIDv7 не угадываются, но защита не на этом | `IdorIntegrationTest` |
| T3 | Форма входа «для вида» | вход — только Keycloak, сервисы — resource server; нет ни одного `permitAll` кроме health/openapi | `SecurityMatrixTest` (эндпоинт × роль) |
| T4 | Вредоносный файл (zip-бомба, PDF с JS, полиглот) | тип по сигнатуре, лимиты размера и страниц, рендер в изолированном ocr (без сети, read-only FS, лимит памяти), PDF не исполняется | тесты приёма |
| T5 | Подмена результата разбора с клиента | правки — только через review с ролью и историей; результат docproc клиент не пишет | матричный тест |

| T7 | Утечка файлов из БД/бэкапа | AES-256-GCM на уровне приложения, ключ в `.env` (не в БД, не в git) | `FileCryptoTest` |
| T8 | Подбор кода возврата | 6 символов + контакт, 5 попыток → блок 15 мин, rate-limit по IP | тест |

| T10 | Повтор/дубликат загрузки | `Idempotency-Key`, `sha256` в пределах заявки | тест |

## 4. ПДн (152-ФЗ) и бонус B-07
- Согласие на обработку — галочка перед созданием заявки (`CONSENT_REQUIRED`), фиксируем время и версию текста.
- Минимизация: соискателю — без значений полей; в очереди оператора номера документов маскированы (`45 ** ****12`), полный номер — по «показать» с записью в аудит.
- Скан открывает только назначенный оператор или старший; каждый просмотр → `access_audit(user, application, file, at, ip)`.
- Удаление заявки (или отзыв согласия) — удаляет файлы, результаты и поля, оставляя обезличенную запись в журнале.
- Модели не уходят в интернет в локальном режиме; при облачном провайдере — предупреждение в README и на защите (ПДн уходят провайдеру).

## 5. Заголовки и транспорт
Caddy: HTTPS (Let's Encrypt или `tls internal`), HSTS, CSP `default-src 'self'` (+ `blob:` для превью), `X-Content-Type-Options`, `Referrer-Policy: no-referrer` (ключ заявки в URL-фрагменте, не в query — не уходит в Referer и логи), `Cache-Control: no-store` для `/files/**` и ответов с ПДн. CORS — только свой origin.
