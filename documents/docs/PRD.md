# PRD — «Документы» (кейс 9.1.2, «СберБизнесВайб»)

Требования с ID — `REQUIREMENTS.md` (источник правды для задач). PRD модулей: `../services/<svc>/docs/PRD.md`, `../frontend/docs/PRD.md`.

## Обзор
Сервис приёма документов соискателей: человек с телефона отвечает на пару вопросов, видит, какие документы нужны именно ему, фотографирует их и сразу видит, что с каждым происходит. Сервер принимает файл мгновенно, а разбор идёт в фоне: текст → тип документа по содержимому → поля по схеме → проверки. Оператор получает очередь, где большая часть полей уже заполнена и проверена, сомнительное подсвечено, а оригинал — рядом. Модель работает и в облаке, и локально без интернета.

## Проблемы
- Документы присылают в мессенджер фотографиями, оператор вручную перепечатывает паспорт, патент, регистрацию — долго и с ошибками.
- Половина фото непригодна (размыто, обрезано, блик), выясняется это через дни.
- Соискатель не знает, какой набор нужен именно ему (гражданство, патент).
- Расхождения между документами (ФИО в паспорте и патенте) находят поздно.
- Документы с ПДн лежат где попало, доступ никем не контролируется.

## Цели (как нас оценивают)
| Цель | Метрика / критерий |
|---|---|
| Точный разбор на закрытом наборе | доля верных полей и типов на своём «закрытом» наборе (EVAL.md); 0 выдуманных полей (30 баллов) |
| Мгновенный приём, честная фоновая обработка | `202` ≤ 300 мс, видимые стадии, рестарт посреди разбора — без потерь (Д7, 10 баллов) |
| Серверные проверки и внятные отказы | каждый код из API.md воспроизводим через UI (12 баллов) |
| Оператор экономит время | «подтверждено автоматически / исправлено» по полям, оригинал рядом, очередь (16 баллов) |
| Модель изолирована и работает локально | Ollama без интернета, обоснованный выбор (Д6, 15 баллов) |
| Инженерная культура | `docker compose up` ≤ 10 мин, CI, документация, коммиты всех, каждый объясняет свой модуль |

## Пользователи
Соискатель (телефон, иногда ноутбук) · оператор приёма · старший оператор · аудитор. Подробно по зонам — `../frontend/docs/PRD.md`.

## Ключевые функции → где живут
| Функция | Модуль |
|---|---|
| Анкета → набор документов, приём, проверки, дубликаты, дозагрузка, файлы | intake |
| Очередь заданий, стадии, OCR-текст, тип, поля, проверки, уверенность | docproc (+ ocr) |
| Модель: облако/локально, журнал вызовов | libs/llm |
| Очередь оператора, сверка, правки, решение, история, выгрузки, метрики, сверка между документами | review |
| Кабинет соискателя и рабочее место оператора | frontend |
| Вход операторов, маршрутизация | Keycloak + gateway |

## MVP
**P0** — сквозной путь: анкета → загрузка → стадии → поля → оператор видит и подтверждает (интеграция №1, Т+3:00), 8 видов на открытом наборе, рестарт без потерь, закрытость, локальная модель, документация. **Затем P1**, бонусы P2 — только после P0+P1 (срезы — `PLAN.md`).
