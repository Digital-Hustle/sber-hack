# PRD — frontend «Документов»

Общий продукт — `../../docs/PRD.md`, требования с ID — `../../docs/REQUIREMENTS.md` (разделы B и E, FR-10…15, FR-50…57). Здесь — только то, что делает интерфейс.

## Обзор
Одно веб-приложение с двумя зонами: **кабинет соискателя** `/apply` (телефон, без пароля — ссылка-ключ заявки) и **рабочее место оператора** `/operator` (десктоп, вход через Keycloak). Судьи проверяют всё руками через интерфейс, поэтому UI — это и есть продукт (12 + 16 баллов).

## Проблемы, которые решаем
- Соискатель не знает, какие документы нужны именно ему, и узнаёт о плохом скане через неделю.
- Фото с телефона размытые, с бликами, обрезанные — нужна подсказка «что сделать» сразу.
- Оператор перепечатывает данные с бумаги и сверяет на глаз; ему нужен оригинал рядом с полями и подсветка сомнительного.

## Цели
1. Соискатель с телефона собирает комплект: анкета → список → загрузка/камера → стадии в реальном времени → «комплект полный» (С1–С3).
2. Каждый отказ и каждая непригодность — текст + что сделать, из ответа бэка.
3. Оператор сверяет документ за минуту: оригинал (зум/поворот, подсветка bbox) рядом с полями, «перепроверить» сверху, горячие клавиши (С13–С18).
4. Каждый экран: loading / empty / error / offline. Ни одного мока в production-сборке; пустая БД → честные нули.

## Пользователи
| Кто | Зона | Устройство | Что важно |
|---|---|---|---|
| Соискатель | `/apply` | свой телефон (iOS Safari / Android Chrome), иногда десктоп | без регистрации, понятный список, камера, крупные кнопки, статусы по-русски |
| Оператор (OPERATOR) | `/operator` | десктоп, 1–2 монитора | очередь, «следующая», оригинал рядом, правки с клавиатуры |
| Старший оператор (SENIOR_OPERATOR) | `/operator` | десктоп | решения, переразбор, отчёты, метрики |
| Аудитор (AUDITOR) | `/operator/history`, `/operator/metrics` | десктоп | история, метрики, ПДн замаскированы |

## Ключевые функции
- **Кабинет (F1):** создание заявки и согласие; анкета (гражданство, цель, срок); список нужных документов с прогрессом; загрузка (drag&drop, выбор, камера с рамкой и подсказкой), несколько страниц в пункт; карточка файла со стадией в реальном времени (SSE) и причиной/подсказкой; «перенесли в другой пункт»; дозагрузка/замена; итог «не хватает X, Y» (B-01); ссылка-ключ и код возобновления.
- **Оператор (F2):** вход SSO; очередь с фильтрами в URL и «взять следующую»; карточка заявки: просмотрщик оригинала (страницы, зум, поворот, подсветка bbox поля) + поля с уверенностью и проверками; правка поля/типа, подтверждение, «запросить переснять», «разобрать заново», решение; расхождения между документами (B-03); история (B-08); истекающие документы + выгрузка (B-04); карточка для кадров (B-05); метрики очереди (B-06); бейдж статуса модели (FR-46).
