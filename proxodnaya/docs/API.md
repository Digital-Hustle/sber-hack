# Контракт API (черновик, финализировать на синке в Т0+0:45)

> Что фронт ждёт от бэкенда по каждому экрану (обратный сваггер, из моков песочницы) — [BACKEND-CONTRACT.md](BACKEND-CONTRACT.md).

Все запросы идут через gateway: `/<service>/api/v1/...` (`people`, `access`, `shift`, `assistant`); gateway переписывает путь в `/api/v1/...` сервиса (паттерн sueta-rnd-back). Ниже префикс сервиса указан в заголовках разделов. Коллекции всегда в обёртке (`{workers: [...], page: {...}}`), request — `*Rq`, response — `*Rs`. Внутренние вызовы между сервисами — `/internal/**`, наружу gateway их не пропускает. Аутентификация: `Authorization: Bearer <JWT>`. Ошибки — `application/problem+json`: `{type, title, status, detail, code, traceId, errors?}` (`detail` — по-русски для человека, `errors` — поля валидации).


**Gateway [есть, GW-01..08].** Наружу — только `/<service>/api/v1/**`; `/internal/**` и actuator сервисов → `404 NOT_FOUND`. Без токена — только `POST /people/api/v1/auth/worker/activate` и `GET /shift/api/v1/stream/{situation,worker}` (по тикету); остальное — `401 UNAUTHORIZED` (подпись, срок и `iss` проверяет gateway, роли — сервис). Свои ошибки gateway (problem+json): `401 UNAUTHORIZED`, `404 NOT_FOUND`, `413 PAYLOAD_TOO_LARGE` (тело > `MAX_BODY`, 5 МБ), `429 RATE_LIMITED` + `Retry-After` (`/people/api/v1/auth/**`, `/access/api/v1/kiosk/attempts`), `503/504 UPSTREAM_UNAVAILABLE` (сервис недоступен / не ответил вовремя). Каждый ответ несёт `X-Request-Id` (свой принимается, если `[A-Za-z0-9._-]{8,64}`); заголовки `X-User-*` от клиента срезаются. CORS — только origin из `CORS_ORIGINS`.
## Auth (people: `/people/api/v1/auth/...`)
Персонал: OIDC через Keycloak (`https://<host>/auth/realms/proxodnaya`, ADR-039), backend проверяет JWT по JWKS. Своих паролей для персонала в API нет.
- **[предложение, песочница ADR-046]** беспарольный вход по коду из письма (Keycloak email-OTP или тонкий слой в people): `POST /auth/staff/code` `{email}` → `{sentTo, expiresAt, resendAt}` (ответ одинаковый для любого адреса; 429 `LOGIN_RESEND_TOO_SOON` раньше 45 с); `POST /auth/staff/code/verify` `{email, code}` → `{accessToken, refreshToken?, expiresAt, user}` (6 цифр, 10 мин, 5 попыток: 400 `LOGIN_CODE_INVALID`, 410 `LOGIN_CODE_EXPIRED`, 429 `LOGIN_CODE_LOCKED`); `GET /auth/staff/me`; `POST /auth/staff/logout`. Сессия 12 ч, `DISABLED` → 401 сразу. Подробно — `docs/BACKEND-CONTRACT.md` §1
- **[есть, PPL-04]** `POST /auth/worker/activate` (без токена) `{inviteCode, deviceId (8–64 символа `[A-Za-z0-9_-]`, без точек), publicKeyJwk (EC P-256, только публичный)}` → `{workerId, serverTime, card: {fullName, position, contractor}}` (`photoThumb`, `sites` — после PPL-06). Ошибки: 400 `INVITE_INVALID` (нет/использован/отозван), 410 `INVITE_EXPIRED`, 403 `WORKER_BLOCKED` (и при выдаче инвайта заблокированному), 409 `DEVICE_ALREADY_BOUND`, 400 `VALIDATION_ERROR` (ключ с `d`, не P-256, точка не на кривой). Прежний телефон рабочего → `REVOKED` (`DeviceRevoked`), новый → `DeviceBound` `{deviceId, workerId, publicKey: JWK}` в `people.device.v1`. Было: (привязка ключа устройства; этим же ключом телефон подписывает офлайн-QR; `card` — кэш для работы без сети)
- **[есть, PPL-05]** `POST /auth/device/challenge` (без токена) `{deviceId}` → `{challenge, expiresAt}` (60 с, одноразовый; выдаётся и для неизвестного id — перебор не раскрывает устройства)
- **[есть, PPL-05]** `POST /auth/device/token` (без токена) `{deviceId, challenge, signature}` → `{accessToken, tokenType: "Bearer", expiresAt}`. `signature` — ECDSA P-256/SHA-256 ключом устройства над `auth|<deviceId>|<challenge>`, base64url (r‖s как у WebCrypto или DER). Токен ES256 (ADR-040): `sub` = workerId, роль `WORKER`, `did`, 10 мин. Ошибки: 400 `CHALLENGE_INVALID` (нет/истёк/использован/чужой), 403 `DEVICE_UNKNOWN`, `DEVICE_REVOKED`, `DEVICE_MISMATCH` (подпись не тем ключом), `WORKER_BLOCKED`
- `GET /internal/people/jwks` — открытые ключи токенов people (только внутренняя сеть)
- `POST /auth/kiosk/pair` (GUARD) `{pairingCode, publicKeyJwk}` → `{kioskId, checkpoint}`; далее все `/kiosk/*` подписываются: `X-Kiosk-Id`, `X-Ts`, `X-Nonce`, `X-Signature`
- **[есть, SH-08]** `GET /shift/api/v1/stream/ticket` (ADMIN/MANAGER/SECURITY_OFFICER/GUARD/WORKER) → `{ticket, stream: situation|worker, expiresAt}` — одноразовый на 30 с (`STREAM_TICKET_TTL`) для `EventSource`; рабочему — на свой поток, персоналу — на обстановку. Открытие: `GET /shift/api/v1/stream/{situation|worker}?ticket=` (без токена); повтор, чужой поток или истёкший тикет → `403 FORBIDDEN`. Каждое событие несёт `id` (`<эпоха>-<номер>`); браузер при переподключении шлёт `Last-Event-ID` и получает пропущенное из буфера (последние 500); после рестарта shift досылки нет — перечитайте сводку. Пульс — комментарий раз в 15 с, соединение закрывается через 30 мин (`EventSource` переподключится сам)

## Worker (device-токен; профиль — people, смены и поток — shift, история — access)
- **QR без запроса к серверу**: `v1.<workerId>.<deviceId>.<window>.<sig>`, `window = floor(unixTime / 30)`, `sig = base64url(ECDSA-P256-SHA256("v1|workerId|deviceId|window"))` в формате WebCrypto (P1363, r‖s, 64 байта; DER тоже принимается). Как в BACKEND-CONTRACT.md и песочнице. Телефон перерисовывает QR каждые 30 с с таймером; часы сверяет по `serverTime` при онлайне.
- **[есть, SH-07]** `GET /shift/api/v1/worker/me` (WORKER) → `{inside, zoneId?, since?, shift?: {shiftId, start, end, windowOk}, workedMsToday}`; «на объекте» — открытый интервал моложе `PRESENCE_TTL`
- **[есть, ACC-11]** `GET /access/api/v1/worker/attempts?cursor&limit` (WORKER) — своя история (рабочий из токена) с причинами, формат как у `GET /attempts`
- **[есть, SH-02]** `GET /shift/api/v1/worker/shifts?from&to&cursor&limit` (WORKER) — свои смены, формат как у `GET /shifts`
- **[есть, SH-11]** `POST /worker/heartbeat` (WORKER) `{lat, lon, accuracy?}` → `{at, insideFence?, distanceM?}` (раз в 60 с; геозона — `SITE_LAT`, `SITE_LON`, `SITE_RADIUS_M`, без координат `insideFence: null`; круг точности в пользу человека)
- `DELETE /worker/me/device` — сотрудник отвязывает свой телефон («Выйти с этого телефона»)
- `POST /people/api/v1/worker/me/face` `{at, signature, photo, liveness: {frames}}` → `{status: PENDING}`; `signature = ECDSA-P256-SHA256("face|workerId|deviceId|at")` ключом телефона, `|now−at| ≤ 5 мин`. Эталон с телефона включается только после `POST /workers/{id}/face/review` (ADR-046)
- `GET /stream/worker` (SSE) **[есть, SH-08: `attempt.result`]**: `attempt.result` `{attemptId, checkpointId, zoneId, direction, decision, reasonCode, ts, simulated}` — только свои проходы; **[есть, SH-13]** `reminder.exit` `{shiftId, shiftEndsAt, ts}` — через `EXIT_REMINDER_AFTER` (30 мин) после конца смены, если выход не отмечен (открыт интервал, начатый в окне смены); одно на смену, до автозакрытия `AUTO_CLOSE_AFTER`

## Kiosk (access: `/access/api/v1/kiosk/...`; роль GUARD + подпись ключом киоска)
- `POST /kiosk/attempts` `{qr, checkpointId}` → `ScanRs` = `{kind: "decision", result: DecisionRs}` | `{kind: "challenge", token, challenge: {kind: turn-left|turn-right|blink|nod, text, timeoutMs}, worker: {id, fullName, position, contractor}}`. Направление выводит сервер (ADR-037): внутри и вход моложе `PRESENCE_TTL` (16 ч) → OUT, иначе IN. Успешный проход того же человека меньше 30 с назад → `REPEAT_SCAN`. `checkpointId` в теле временно — до подписи запросов киоска (ACC-12), потом берётся из ключа киоска.
- `POST /kiosk/attempts/{token}/frames` `{frames: [base64 jpeg]}` → `DecisionRs = {attemptId, decision: ALLOW|DENY, code, message, hint, worker?, direction, score?, ts}`. Токен одноразовый (повтор → 404). На этом шаге QR гасится при любом итоге (один QR — один челлендж); тот же QR, уже погашенный на другом киоске → `QR_REUSED`. Выход не требует смены и допуска.
- **[есть, ACC-13]** `POST /kiosk/manual` (GUARD) `{workerId, checkpointId, note (3..500)}` → `DecisionRs` с `decision: MANUAL`, `code: MANUAL_GUARD`, `source=MANUAL`. Снимает проверки QR, лица и смены, но не блокировку (`WORKER_BLOCKED`); направление — сервер, как у киоска; причина и охранник (`sub` токена) — в журнале. Неизвестные рабочий/проходная → 404, people недоступен → `SYSTEM_ERROR`.
- Anti-passback **[есть, ACC-09]**: присутствие блокируется в транзакции решения; если за время челленджа направление сменилось (второй киоск успел пропустить) → `ALREADY_INSIDE` / `NOT_INSIDE`. **[есть, ACC-17]** Вместимость зоны: вход в зону с `capacity` (people) сверяется со счётчиком «внутри» (`worker_state.zone_id`, вход моложе `PRESENCE_TTL`) под блокировкой зоны в той же транзакции; мест нет → `ZONE_FULL`, присутствие не меняется. Выход и ручной проход охранника вместимостью не ограничены. `capacity` не задана → без ограничения.
- `POST /security/journal/verify` (SECURITY_OFFICER, ADMIN) → `{ok, checked, brokenAt?}` — проверка hash-chain журнала.

- `GET /kiosk/offline-snapshot` → `{issuedAt, expiresAt, workers: [{id, name, photoThumb, devices: [{deviceId, publicKeyJwk}], shiftWindow, permitsValidUntil}], codes?: {service?, guard?}, signature}` (ADR-029, только при `OFFLINE_MODE_ENABLED`; `codes` — PBKDF2-хэши кодов терминала `{salt, hash, iter, digits}`, чтобы код охранника проверялся без связи)
- `POST /kiosk/identify` `{frames}` → решение (режим «Сначала лицо», 1:N со строгим порогом)
- `POST /kiosk/offline-attempts` `{attempts: [{localId, ts, qr, direction, guardDecision, guardReason, prevHash, hash}]}` → `{accepted, conflicts: [...]}`

## Внутренние API (только service accounts)
Вызывающий сервис получает токен по OAuth2 client-credentials (Keycloak, клиент `svc-<service>` с service account и ролью `SVC_<SERVICE>`); access **[есть]**: клиент `svc-access`, секрет `KC_SVC_ACCESS_SECRET`, токен навешивается на все клиенты face/people/shift. access берёт зону пункта пропуска из people: неизвестный пункт → 404 без записи в журнал, зона вне `zoneIds` → `NO_ZONE_PERMIT`.
- face **[есть, FACE-01..05/07]** (порт 8090, токен с `aud=face`): `POST /internal/face/verify` (роль `SVC_ACCESS`) `{workerId, frames[1..5] (JPEG base64 или data-URL, ≤ 2 МБ), challenge: TURN_LEFT|TURN_RIGHT|NOD}` → `{match, score, liveness, quality, reason?}`; `reason` — первая причина из `FACE_NOT_FOUND`, `FACE_MULTIPLE`, `FACE_LOW_QUALITY`, `FACE_NOT_ENROLLED`, `FACE_MISMATCH`, `LIVENESS_FAILED`; `BLINK` по 5 точкам не определяется → всегда `liveness: false`. Роль `SVC_PEOPLE`: `POST /internal/face/enroll` `{workerId, frames[1..3], replace = true}` → `{accepted, quality, templates}` (≤ 5 свежих эталонов; плохой снимок → `422 FACE_LOW_QUALITY`, `errors[0].code` ∈ `NO_FACE|MULTIPLE|TOO_SMALL|TOO_DARK|TOO_BRIGHT|BLURRY`, разные люди на снимках → `422 FACE_MULTIPLE`); `POST /internal/face/check` `{photo}` → `{ok, code, quality, message}`; `DELETE /internal/face/workers/{id}` → 204. Битый кадр → `400 FRAME_INVALID`, больше лимита → `413`
- people **[есть]** (роль `SVC_ACCESS`): `GET /internal/people/workers/{id}/access-profile` → `{status, fullName, position, contractor, deviceIds (действующие), permits: [{type, validUntil}], zoneIds}`, 404 — рабочего нет; `GET /internal/people/checkpoints/{id}` → `{id, zoneId, siteId, name, zoneCapacity?}` (`zoneCapacity` — ACC-17)
- shift **[есть, SH-03]** (роль `SVC_ACCESS`): `GET /internal/shift/workers/{id}/active-shift?at=` → `{shiftId, start, end, windowOk}`: `windowOk` — `start − SHIFT_EARLY_ENTRY (60 мин) ≤ at < end`; вне окна, но смена в тот же день площадки → `windowOk: false`; смен в этот день нет → 404
- access: `GET /internal/access/stats?...` (для assistant)
