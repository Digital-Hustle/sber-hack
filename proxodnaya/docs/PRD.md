# PRD — «Проходная» (кейс 1, «СберБизнесВайб»)

Требования с ID и приоритетами — `REQUIREMENTS.md` (источник правды для задач). PRD модулей: `../services/<svc>/docs/PRD.md`, `../frontend/docs/PRD.md`.

## Обзор
Система контроля и учёта людей на стройплощадке: рабочий проходит по динамическому QR со своего телефона (работает без сети) и сверке лица, сервер решает «пустить/не пустить» и пишет неизменяемый журнал, из которого считаются смены, отработанное время и аналитика. Руководитель видит обстановку в реальном времени и задаёт вопросы помощнику на LLM, который не выдумывает цифры.

## Проблемы
- Бумажный журнал и «свой» охранник: проходят по чужим пропускам, время прихода/ухода недостоверно.
- У рабочих нет корпоративных аккаунтов, на площадке слабая связь.
- Подрядчики выставляют часы, которые нечем проверить; табель собирают руками.
- Нарушения ТБ: просроченный инструктаж/медосмотр, скопления людей в опасной зоне.

## Цели (как нас оценивают)
| Цель | Метрика / критерий |
|---|---|
| Нельзя пройти за другого | чек-лист H: чужой QR + чужое лицо, фото на телефоне, скриншот, повтор QR → отказ (Д10, 28 баллов) |
| Решение только на сервере, fail-closed | `stop face` → DENY `SYSTEM_ERROR` (Д2) |
| Заведение человека и первый проход через UI | ≤ 2 минуты (Д9) |
| Честные смены и аналитика | интервалы с ночными сменами, «как посчитано», неполные данные отдельно (22 балла) |
| Помощник без выдумок, работает локально | валидатор чисел, Ollama без интернета (Д5, Д6, 15 баллов) |
| Инженерная культура | `docker compose up` ≤ 10 мин, CI, документация, коммиты всех 5, каждый объясняет свой модуль (Д1, Д7, Д8, Д11) |

## Пользователи
Рабочий (телефон, PWA) · охранник (киоск) · администратор · руководитель/прораб · офицер безопасности. Подробно по зонам — `../frontend/docs/PRD.md`.

## Ключевые функции → где живут
| Функция | Модуль |
|---|---|
| Офлайн-QR, подписанный ключом устройства | frontend `/worker` + people (ключи) + access (проверка) |
| Проход: QR → лицо 1:1 → живость → правила → ALLOW/DENY | access (+ face, people, shift) |
| Журнал попыток, hash-chain, целостность | access |
| Люди, допуски, устройства, зоны, проходные | people |
| Смены, интервалы, табель, аналитика, оповещения, SSE | shift |
| Помощник с инструментами и валидатором | assistant |
| Киоск, телефон, админка | frontend |
| Вход персонала (SSO, TOTP), маршрутизация | Keycloak + gateway |

## MVP
**Обязательно (P0):** всё с приоритетом P0 в `REQUIREMENTS.md` — сквозной проход человека, заведённого через UI (интеграция №1, Т+3:00), fail-closed, журнал, локальная LLM, документация, compose. **Затем P1**, бонусы P2 — только после закрытия P0+P1 (срезы scope — `PLAN.md`).
