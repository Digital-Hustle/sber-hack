# PRD — frontend «Проходной»

Общий продукт — `../../docs/PRD.md`, требования с ID — `../../docs/REQUIREMENTS.md` (раздел E, FR-50…54). Здесь — только то, что делает интерфейс.

## Обзор
Одно веб-приложение с тремя зонами под три типа устройств: **киоск** на проходной (ноутбук/планшет с камерой), **телефон рабочего** (PWA без пароля), **админка** для офиса. Судьи проверяют всё руками через интерфейс (FR-53), поэтому UI — это и есть продукт.

## Проблемы, которые решаем
- На проходной стройки ставят галочки в бумажном журнале: можно пройти по чужому пропуску, данные о времени недостоверны.
- У рабочих нет корпоративных аккаунтов и часто нет мобильного интернета на площадке.
- Охраннику нужен ответ за 2 секунды и понятный без чтения: «зелёный — проходи, красный — вот почему».
- Руководителю нужны честные цифры «кто сейчас на объекте» и «сколько отработано», а не красивые графики на пустых данных.

## Цели
1. Сквозной проход человека, заведённого через UI, за ≤ 2 минуты от заведения до прохода (Д9).
2. Вердикт на киоске ≤ 2 с (p95) после кадров, понятный с 3 метров.
3. QR на телефоне работает без сети (Д10, NFR-20).
4. Каждый экран: loading / empty / error / offline (FR-54). Ни одного мока в production-сборке.
5. Визуально — Сбер (Nova): судьи-сотрудники Сбера узнают стиль.

## Пользователи
| Кто | Зона | Устройство | Что важно |
|---|---|---|---|
| Охранник (GUARD) | `/kiosk` | ноутбук/планшет, камера, стоя | крупно, без лишних кликов, звук, ручной проход с причиной |
| Рабочий | `/worker` | свой телефон, iOS Safari / Android Chrome, часто без сети | QR открывается мгновенно, статус и история, без пароля |
| Администратор (ADMIN) | `/admin` | десктоп | быстро завести человека, фото с вебкамеры, инвайт, смены |
| Руководитель (MANAGER) | `/admin` | десктоп/планшет | обстановка сейчас, аналитика с фильтрами, помощник |
| Офицер безопасности (SECURITY_OFFICER) | `/admin/security` | десктоп | аудит, целостность журнала, отказы |

## Ключевые функции
- **Киоск (F1):** SSO охранника + сопряжение ключа киоска; авто-скан QR; челлендж живости с подсказкой и таймером; экран вердикта (ALLOW/DENY/MANUAL/ERROR, причина, что делать, звук, автосброс); вход/выход; индикатор связи; офлайн-режим за флагом (FR-70).
- **Телефон (F1):** активация по инвайту (ключ ECDSA в IndexedDB); динамический QR с кольцевым таймером 30 с; статус «на объекте / нет», зона, смена, отработано; история проходов с причинами; график смен; баннер «нет связи».
- **Админка (F2):** люди (CRUD, фото с вебкамеры, инвайт-QR, блок), устройства, зоны и проходные (код сопряжения киоска), смены и шаблоны, журнал с фильтрами в URL, интервалы, дашборд «сейчас на объекте», аналитика с «как посчитано», помощник (текст + источники + таблица), настройки порогов, страница «Безопасность».

## MVP (P0 — без этого ноль)
| Зона | Обязательно | Потом (P1/P2) |
|---|---|---|
| kiosk | скан QR → кадры → вердикт с кодом/текстом/подсказкой; вход/выход; ошибки сети | челлендж-анимации, звук, офлайн-режим, ручной проход |
| worker | активация, офлайн-QR с таймером, статус | история, смены, напоминание о выходе (B-04) |
| admin | заведение человека за 2 мин (ФИО → фото → инвайт → смена), журнал, люди, дашборд «сейчас» | аналитика и графики бонусов, помощник-чат, «Безопасность», SSE realtime |

Метрики успеха: прогон чек-листа H из REQUIREMENTS без провалов; 0 нарушений `fsd-check`/`guard`; Lighthouse PWA для `/worker` проходит.
