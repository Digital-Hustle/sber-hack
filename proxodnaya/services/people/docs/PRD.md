# PRD — people

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот сервис.

## Обзор
Справочник «кто есть кто»: рабочие и подрядчики, допуски (инструктаж, медосмотр, зоны), телефоны рабочих и их публичные ключи, зоны и проходные, сопряжение киосков, персонал в Keycloak. Выдаёт device-токены рабочим без паролей.

## Проблемы
- У рабочих нет аккаунтов и паролей, телефоны меняются, интернета на площадке может не быть.
- Допуски (ТБ, медосмотр, зона) хранятся на бумаге и не проверяются на проходной.
- Админ должен завести человека за 2 минуты (Д9) — без ручной работы в Keycloak.
- Access должен знать ключи устройств без синхронного вызова на каждый проход.

## Цели
1. Заведение человека → инвайт → активация телефона за ≤ 2 минуты.
2. Ключ устройства неизвлекаемый, на сервере только публичный; перепривязка — только админом.
3. Каждое изменение рабочего/устройства уходит событием через outbox (Д4) — проекции в access и shift актуальны.
4. Персонал заводится из админки (provisioner в Keycloak), без ручных действий в консоли Keycloak.

## Пользователи
- ADMIN — CRUD людей, допусков, зон, проходных, устройств, персонала.
- Рабочий (телефон) — активация, challenge, device-токен, профиль.
- Охранник (киоск) — сопряжение киоска кодом.
- access, shift — через события и `/internal/people/**`.

## Ключевые функции
- Рабочие и подрядчики: CRUD, блокировка, удаление (с удалением биометрии в face).
- Допуски: инструктаж ТБ, медосмотр (срок), допуски в зоны.
- Инвайт: одноразовый код + QR, срок жизни; активация `{inviteCode, deviceId, publicKeyJwk}`.
- Device-auth: challenge → подпись ключом устройства → device-токен ES256 10 мин; JWKS для gateway и сервисов.
- Зоны, проходные, код сопряжения киоска → ключ киоска (для подписи запросов, FR-64).
- `/internal/people/workers/{id}/access-profile` для access; события `people.worker.v1`, `people.device.v1`.
- Provisioning персонала (ADMIN/MANAGER/SECURITY_OFFICER/GUARD) в Keycloak через service account.
