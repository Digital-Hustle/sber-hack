# PRD — gateway

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот сервис.

## Обзор
Единая точка входа для всех трёх зон фронтенда: один origin, одна проверка токена на входе, маршрутизация на 4 Java-сервиса. Сервисы и Kafka во внутренней сети и наружу не торчат (zero-trust, ADR-015).

## Проблемы
- Пять сервисов на разных портах — фронту нужен один адрес, один CORS и один TLS.
- Два вида токенов: персонал (Keycloak) и рабочие (device-токен ES256 от people) — оба нужно принимать.
- Перебор QR/пин-кодов и флуд кадрами на киоске должны резаться до сервисов.
- Внутренние API (`/internal/**`) не должны быть доступны снаружи даже по ошибке.

## Цели
1. Только gateway открыт наружу; `/internal/**` → 404 на входе.
2. JWT проверяется на входе (multi-issuer), но каждый сервис всё равно проверяет его сам (defense in depth).
3. `traceparent`/`X-Request-Id` на каждый запрос — проход виден одним трейсом в Jaeger (NFR-18).
4. Добавление сервиса = одна запись маршрута.

## Пользователи
- Фронтенд (все зоны) — через `https://<host>/<svc>/api/v1/**`.
- Судьи и команда — косвенно: Swagger агрегатор (если успеем), health.

## Ключевые функции
- `RewritePath /<svc>/api/v1/** → /api/v1/**` для people, access, shift, assistant (паттерн sueta-rnd-back).
- OAuth2 Resource Server (WebFlux), issuers: Keycloak realm + people (device-токены, JWKS `/people/api/v1/.well-known/jwks.json`).
- Публичные без токена: `/people/api/v1/auth/**` (активация, challenge), health.
- CORS только свои origin; лимит тела (кадры: до 5 МБ на `/access/api/v1/kiosk/**`).
- Rate-limit на `/auth/**` и `/kiosk/attempts` (in-memory счётчики допустимы — это не данные; Redis нельзя по лицензии).
- SSE проксируется без буферизации, таймаут ответа для `/stream/**` отключён.
