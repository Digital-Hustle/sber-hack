# PRD — face

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот сервис.

## Обзор
Внутренний сервис биометрии: принимает кадры, проверяет качество и что в кадре ровно одно лицо, считает эмбеддинг SFace, сравнивает с зашифрованным эталоном **именно этого** рабочего и проверяет живость (активный челлендж + MiniFASNet). Возвращает факты (`match, score, liveness, quality, reason`) — решение принимает access.

## Проблемы
- Пройти по чужому QR можно, если не сверять лицо с владельцем (Д10).
- Фото на телефоне перед камерой — классическая атака на распознавание.
- Биометрия — ПДн особой категории (152-ФЗ): утечка БД не должна раскрывать эмбеддинги.
- Плохой свет, очки, несколько людей в кадре — нужны понятные отказы, а не «не совпало».

## Цели
1. Верное совпадение своих и отказ чужим на фото команды; порог из настроек, матмодель FAR/FRR для защиты.
2. Время на кадр ≤ 150 мс на CPU ноутбука; ответ на 3–5 кадров ≤ 1 с (укладываемся в таймаут access 1,5 с).
3. Эмбеддинги в БД только зашифрованы AES-256-GCM; фото не храним.
4. Отказы `FACE_NOT_FOUND`, `FACE_MULTIPLE`, `FACE_LOW_QUALITY`, `FACE_MISMATCH`, `LIVENESS_FAILED` различимы.

## Пользователи
- access (verify) и people (delete) — только по service account.
- ADMIN — заведение эталона через people/админку (`POST /workers/{id}/face`).

## Ключевые функции
- Enroll: 1–3 кадра → качество (размер лица, резкость, яркость) → YuNet → SFace 128-d → AES-GCM → `face_templates`.
- Verify 1:1: кадры → одно лицо в каждом → тот же человек во всех кадрах → косинус с эталонами рабочего ≥ порога.
- Живость: челлендж (поворот головы по landmarks YuNet, yaw в нужную сторону) + MiniFASNet на кадре (P2).
- Удаление эталонов рабочего; `model_version` у эталона.
- Метрики `face_score`, время инференса; OTel FastAPI.
