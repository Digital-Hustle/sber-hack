# PRD — assistant

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот сервис.

## Обзор
Отвечает на вопросы руководителя по-русски («кто опоздал сегодня», «сколько часов отработал подрядчик X за неделю») через инструменты (function calling) поверх read-only API shift и access. Модель не видит БД и не считает — числа приходят из инструментов и проверяются валидатором. Работает с GigaChat, OpenAI-совместимым API или локальной Ollama.

## Проблемы
- LLM выдумывает цифры — для отчётов по рабочему времени это недопустимо (С18–С20).
- На площадке может не быть интернета — нужен локальный режим (Д6).
- Сбой модели не должен влиять на проходы и на остальную админку.
- Prompt injection через ФИО/комментарии в данных.

## Цели
1. 0 чисел в ответе, которых нет в результатах инструментов; иначе одна перегенерация, затем честный отказ с сырыми данными.
2. Переключение провайдера только переменной `LLM_PROVIDER`, без изменений кода.
3. Ответ ≤ 30 с, circuit breaker, понятное сообщение при сбое.
4. Журнал обращений: провайдер, модель, latency, токены, вердикт валидатора.

## Пользователи
- MANAGER и ADMIN — чат помощника в админке.
- Проактивная лента «Помощник заметил» (B-09).

## Ключевые функции
- `LlmGateway` + адаптеры `gigachat`, `openai`, `ollama` (`@ConditionalOnProperty`).
- Инструменты: `get_on_site_now`, `get_hours`, `get_late_overtime`, `get_refusals`, `get_attempts`, … — read-only `/internal/**` shift и access с service-токеном.
- `NumberValidator` с нормализацией (12,5 / 12.5 / проценты), `sources` в ответе (какие инструменты, параметры, момент данных).
- `POST /assistant/ask`, `GET /assistant/status`, `GET /assistant/insights`.
- Аномалии каждые 15 мин правилами, модель формулирует сводку с числами из правил (B-09).
