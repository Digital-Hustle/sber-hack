# PRD — access

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот сервис.

## Обзор
Ядро «Проходной»: принимает QR и кадры с киоска, проверяет подпись и окно QR, атомарно гасит его, параллельно спрашивает face/people/shift, применяет правила и выдаёт ALLOW/DENY с понятной причиной. Ведёт журнал всех попыток с hash-chain и состояние «внутри/снаружи».

## Проблемы
- Проход по чужому пропуску, скриншоту или пересланному QR (Д10, снятие).
- Решение на клиенте можно подделать (Д2, снятие).
- Сбой одной из зависимостей не должен открывать турникет.
- Журнал должен быть полным и неизменяемым — на него опираются отчёты и разбор инцидентов.

## Цели
1. p95 решения ≤ 2,5 с с параллельными вызовами (NFR-16).
2. Повтор QR невозможен даже при гонке: 20 параллельных гашений → 1 успех.
3. Каждый код отказа из `docs/API.md` воспроизводим и покрыт тестом.
4. Падение shift/assistant/Kafka не останавливает проходы (NFR-19).

## Пользователи
- Охранник через киоск (`/kiosk/*`).
- Рабочий — история своих проходов (`/worker/attempts`).
- ADMIN/MANAGER — журнал с фильтрами; SECURITY_OFFICER — целостность журнала.
- shift, assistant — события `access.pass.v1` и `/internal/access/**`.

## Ключевые функции
- `POST /kiosk/attempts` — формат QR → устройство (проекция) → подпись ECDSA → окно ±90 с → гашение → челлендж живости.
- `POST /kiosk/attempts/{id}/frames` — параллельно face (1:1 + живость), people (access-profile), shift (активная смена), таймаут 1,5 с, CB.
- `DecisionEngine` — порядок проверок из `../../docs/ARCHITECTURE.md`, первая проваленная = причина.
- Anti-passback, вместимость зоны, TEMP_LOCKED после 5 неудачных сверок за 10 мин.
- Журнал `pass_attempts` (append-only, триггер, hash-chain), `POST /security/journal/verify`.
- Ручной проход охранника `MANUAL` с причиной (FR-14); офлайн-снимок и приём офлайн-журнала (FR-70, флаг).
- Проверка подписи запросов киоска (FR-64); `/internal/access/stats` для assistant.
