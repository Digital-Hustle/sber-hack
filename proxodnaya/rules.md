# rules.md — правила для людей и агентов

> Каждое правило ниже защищает от снятия с конкурса или от потери баллов. Номера в скобках — ссылки на критерии положения (Д = допуск, СН = снятие, Б = бонус).

## 1. Красные линии (нарушение = снятие)
1. **Решение о проходе принимает только сервер** (Д2, СН). Клиент (киоск, телефон) присылает сырые данные: кадры, токен, id проходной. Ответ `ALLOW/DENY` формирует только `access.DecisionEngine`. На клиенте нет `if (match) allow`.
2. **Проверка лица — сравнение с эталоном конкретного человека** (СН). Запрещено «есть лицо в кадре → пропустить». Всегда: детекция → эмбеддинг → косинусная близость с эталоном заявленного человека → порог из настроек → проверка живости.
3. **Подтверждение личности динамическое** (Д10, СН). QR/токен рабочего одноразовый, живёт ≤ 30 с, подписан сервером, привязан к устройству, гасится атомарно при первом использовании. Скриншот или повтор не работает.
4. **Только PostgreSQL** (Д4, СН). Keycloak тоже хранит данные в PostgreSQL, а не во встроенной H2. Никаких `Map` в памяти как хранилища, H2, SQLite, JSON-файлов рядом с кодом. Кэш допустим только поверх БД.
5. **Аналитика и обстановка считаются только из реальных событий в БД** (СН). Никаких захардкоженных графиков и цифр. Демо-генератор, если он есть, пишет через тот же доменный сервис с `source=SIMULATOR`, а интерфейс это помечает.
6. **Помощник не выдумывает числа** (СН). Все числа берутся из вызовов инструментов (SQL на сервере). Валидатор ответа проверяет, что каждое число есть в данных инструментов, иначе ответ блокируется.
7. **Модель вызывается по-настоящему** (Д5, СН). Никаких `return "заготовленный ответ"`, даже как запасной вариант. Если модель недоступна, честно показываем «Помощник недоступен: <причина>».
8. **Никаких секретов в git** (Д7, СН). Ключи только в `.env` (он в `.gitignore`), в репозитории лежит только `.env.example`. Pre-commit хук `gitleaks`. Если секрет утёк в историю, ротируем ключ и переписываем историю немедленно.
9. **Каждый понимает свой код** (Д11, СН). Не мержим код, который владелец не может объяснить за 60 секунд. Агент пишет, человек читает и отвечает.
10. **Без вирусных лицензий** (п. 5.8.4 положения). Запрещены GPL/AGPL/SSPL (например MinIO, Grafana, iText, ghostscript-зависимости). Разрешены MIT/Apache-2.0/BSD/ISC/PostgreSQL/MPL. Новая зависимость = строка в `docs/DECISIONS.md` с лицензией.
11. **Код пишется только на хакатоне** (п. 7.3). До старта готовим только документы, правила и знания. Репозиторий создаём в день мероприятия, первый коммит — после старта.

## 2. Архитектура
- Модульный монолит. Пакет `ru.team.gate.<module>`, внутри `api` (публичные интерфейсы и DTO), `domain`, `infra`, `web`. Другие модули ходят только через `api`. Контролируем тестами ArchUnit.
- Вызовы LLM только через порт `llm.api.ChatModelPort`. SDK и HTTP-клиенты провайдеров импортируются только в `llm.infra.*`. Это проверяет ArchUnit-тест.
- Вызовы лицевой модели только через порт `face.api.FaceEngine`.
- Время берётся только серверное (`Clock`, внедряется бином). Метки времени от клиента игнорируем.
- Ни одна ошибка не превращается в `ALLOW`: принцип fail-closed. Исключение в движке = `DENY` с `SYSTEM_ERROR` и запись в журнал.
- Каждая попытка прохода, успешная или нет, пишется в `pass_attempts` в той же транзакции, что и решение.

## 3. Backend-конвенции (Java)
- Java 21, Spring Boot 3.x, Maven wrapper. Lombok разрешён только для `@RequiredArgsConstructor` и `@Slf4j`; DTO делаем через `record`.
- Миграции только через Flyway: `V<n>__<snake>.sql`. Уже применённую миграцию не редактируем никогда.
- Ошибки отдаём в формате RFC 7807 `application/problem+json` с полями `code` (из API.md) и `message` (по-русски, для человека).
- Валидация на входе через `jakarta.validation`. Контроллеры тонкие, логика живёт в сервисах.
- Обязательные тесты: движок решений (по тесту на каждый код отказа), алгоритм интервалов, валидатор чисел помощника, гашение токена при гонке. Интеграционные тесты на Testcontainers + Postgres.
- Логи в JSON, в каждой строке `requestId`. ПДн (фото, эмбеддинги) не логируем.

## 4. Frontend-конвенции
- React 18 + TypeScript strict + Vite. Mantine UI. TanStack Query для серверного состояния. Глобальных сторов без нужды не заводим.
- API-клиент генерируется из OpenAPI (`packages/api`). Руками fetch не пишем.
- Весь интерфейс на русском. Каждый код отказа имеет человеческий текст и подсказку, что делать («Подойдите ближе к камере», «Обновите QR в телефоне»).
- У каждого экрана четыре состояния: загрузка, пусто, ошибка (с кнопкой «Повторить»), данные. Отдельно обрабатываем потерю сети.
- Киоск: полноэкранный режим, крупный шрифт, цвет и звук результата, автосброс за 3 с. Телефон: mobile-first, тач-цели от 48 px, PWA. Админка: desktop, таблицы с фильтрами.

## 5. Git
- Trunk-based: короткие ветки `feat/FR-12-token-consume`, мерж в `main` только через PR по зелёному CI. Ветка живёт меньше 2 часов.
- Conventional Commits: `feat(access): FR-12 атомарное гашение токена`. Коммиты маленькие и частые (история работы — часть оценки, Д7).
- Коммитит тот человек, кто писал с агентом, под своим именем, чтобы история показывала вклад каждого.
- Никаких `node_modules`, `target/`, `.env`, моделей и фото в git.
- Каждые 2 часа тегаем стабильную точку `demo-N`, на которую можно откатиться перед защитой.

## 5.1 Работа агентов через PR
- Цикл и скрипты описаны в скилле `../.agents/skills/proxodnaya-dev/SKILL.md`: ID → ветка → `scripts/verify.sh` + `scripts/guard.sh` → `scripts/open-pr.sh`.
- Агент не мержит и не апрувит. Мерж делает человек-владелец (CODEOWNERS) после зелёного CI.
- Миграции — только через `scripts/new-migration.sh` (метка времени, ADR-012). Контракт — snapshot `contracts/openapi.json` (ADR-013).
- После clone: `scripts/install-hooks.sh` (pre-commit: gitleaks + guard).

## 6. Definition of Done для задачи
- [ ] Требование FR/NFR закрыто, ID указан в коммите
- [ ] Работает через интерфейс, а не только через curl (Д3)
- [ ] Ошибки внятные, коды из API.md
- [ ] Событие пишется в журнал/БД и переживает рестарт
- [ ] Тест или шаг в `scripts/smoke.sh`
- [ ] Владелец может объяснить код
- [ ] Документация/ADR обновлены, если поменялось поведение
