# rules.md — правила для людей и агентов

> Каждое правило ниже защищает от снятия с конкурса или от потери баллов. Номера в скобках — ссылки на критерии положения (Д = допуск, СН = снятие, Б = бонус).

## 1. Красные линии (нарушение = снятие)
1. **Решение о проходе принимает только сервер** (Д2, СН). Клиент (киоск, телефон) присылает сырые данные: кадры, QR, id проходной. Ответ `ALLOW/DENY` формирует только `DecisionEngine` в access. На клиенте нет `if (match) allow`. Офлайн-режим киоска (ADR-029, флаг `OFFLINE_MODE_ENABLED=false` по умолчанию) — это **ручной проход охранника**: киоск только показывает проверку подписи и фото, решение и ответственность — у GUARD, запись досылается на сервер с `source=OFFLINE`.
2. **Проверка лица — сравнение с эталоном конкретного человека** (СН). Запрещено «есть лицо в кадре → пропустить». Всегда: детекция → эмбеддинг → косинусная близость с эталоном заявленного человека → порог из настроек → проверка живости.
3. **Подтверждение личности динамическое** (Д10, СН). QR рабочего формирует телефон без сети: `deviceId + окно времени (30 с)`, подписанные неизвлекаемым ключом ECDSA устройства. Сервер проверяет подпись по публичному ключу, окно (±90 с) и **гасит пару (устройство, окно) атомарно** при первом использовании. Скриншот, пересылка и повтор не работают; плюс сверка лица (ADR-028).
4. **Только PostgreSQL** (Д4, СН). Keycloak тоже хранит данные в PostgreSQL, а не во встроенной H2. Никаких `Map` в памяти как хранилища, H2, SQLite, JSON-файлов рядом с кодом. Кэш допустим только поверх БД.
5. **Аналитика и обстановка считаются только из реальных событий в БД** (СН). Никаких захардкоженных графиков и цифр. Демо-генератор, если он есть, пишет через тот же доменный сервис с `source=SIMULATOR`, а интерфейс это помечает.
6. **Помощник не выдумывает числа** (СН). Все числа берутся из вызовов инструментов (SQL на сервере). Валидатор ответа проверяет, что каждое число есть в данных инструментов, иначе ответ блокируется.
7. **Модель вызывается по-настоящему** (Д5, СН). Никаких `return "заготовленный ответ"`, даже как запасной вариант. Если модель недоступна, честно показываем «Помощник недоступен: <причина>».
8. **Никаких секретов в git** (Д7, СН). Ключи только в `.env` (он в `.gitignore`), в репозитории лежит только `.env.example`. Pre-commit хук `gitleaks`. Если секрет утёк в историю, ротируем ключ и переписываем историю немедленно.
9. **Каждый понимает свой код** (Д11, СН). Не мержим код, который владелец не может объяснить за 60 секунд. Агент пишет, человек читает и отвечает.
10. **Без вирусных лицензий** (п. 5.8.4 положения). Запрещены GPL/AGPL/SSPL (например MinIO, Grafana, iText, ghostscript-зависимости) и веса моделей «только для некоммерческого использования» (InsightFace). Разрешены MIT/Apache-2.0/BSD/ISC/PostgreSQL/MPL. Новая зависимость = строка в `docs/DECISIONS.md` с лицензией.
11. **Код пишется только на хакатоне** (п. 7.3). До старта готовим только документы, правила и знания. Репозиторий создаём в день мероприятия, первый коммит — после старта.

## 2. Архитектура (микросервисы, ADR-015)
- Сервисы в `services/<name>/`, общая библиотека `services/libs/common` (только инфраструктура, без бизнес-логики).
- **Гашение токена + решение + журнал + outbox — только в access-service и в одной транзакции.** Не выносить и не делить.
- Сервис не ходит в чужую БД. Данные другого сервиса берутся через его `/internal/**` API или из событий.
- Синхронные вызовы только в пути прохода (access → face/people/shift), всегда с таймаутом и circuit breaker. Ошибка = `DENY SYSTEM_ERROR`.
- Остальное взаимодействие — события через Kafka (ADR-024): публикация только через outbox, потребитель идемпотентен по `eventId`, топик `<владелец>.<агрегат>.v<N>`.
- Меняешь контракт (REST или событие) → обнови `contracts/` и всех потребителей в том же PR либо сделай изменение обратно совместимым.
- Вызовы LLM только через `LlmGateway` в assistant; распознавание лиц только в Python-сервисе face (ADR-025). Внешние системы — только через `...Gateway`.
- Время только серверное (`Clock`). Fail-closed везде в пути прохода.

## 3. Backend-конвенции (Java)
- **Полные правила — скилл `../.agents/skills/backend-spring/SKILL.md`** (по эталонам команды sueta-rnd-back и certis-api). Ниже — главное.
- Java 21, Spring Boot 3.5, Gradle Kotlin DSL: один wrapper, version catalog, convention plugins (ADR-022). Версии только в `services/gradle/libs.versions.toml`.
- Пакеты: `api/controller` (интерфейс) + `api/controller/impl`, `api/dto/request/*Rq`, `api/dto/response/*Rs`, `features/<f>/{command,query,application,api,spi,gateway}` (ADR-026). Проверяют ArchUnit и `be-check.mjs`.
- Lombok: `@RequiredArgsConstructor`, `@Getter`, `@Builder`, `@Slf4j`; без `@Data` и `@SneakyThrows`. DTO — `record`. MapStruct с `unmappedTargetPolicy = ERROR`.
- БД: jOOQ (codegen из схемы) + Liquibase (ADR-023). Миграции только `scripts/new-migration.sh <service> <slug>` (formatted SQL с меткой времени). Смерженный changeset не редактируем никогда.
- Ошибки отдаём в формате RFC 7807 `application/problem+json` с полями `code` (из API.md) и `message` (по-русски, для человека).
- Валидация на входе через `jakarta.validation`. Контроллеры тонкие, логика живёт в сервисах.
- Обязательные тесты: движок решений (по тесту на каждый код отказа), алгоритм интервалов, валидатор чисел помощника, гашение QR при гонке. `units/` — Mockito, `integrations/` — наследники `AbstractIntegrationTest` (Testcontainers: Postgres + Kafka). CI тесты не пропускает.
- Python (face): `uv`, `ruff`, `mypy --strict`, `pytest`; FastAPI, pydantic `*Rq/*Rs`, ошибки — `application/problem+json`.
- Логи в JSON, в каждой строке `requestId`. ПДн (фото, эмбеддинги) не логируем.

## 4. Frontend-конвенции
- **Полные правила — скилл `../.agents/skills/frontend-fsd/SKILL.md`** (по эталону команды hackathon-spring-2026-frontend). Ниже — главное.
- Одно приложение Vite + React 19 + TypeScript strict, Feature-Sliced Design: `app → pages → widgets → features → entities → shared`, зоны `/kiosk`, `/worker`, `/admin` с ролевыми guard'ами (ADR-020). Импорты проверяет `fsd-check.mjs`.
- Tailwind 4 + shadcn/ui, axios (`$api`), TanStack Query (фабрики ключей в entities), zustand, react-hook-form + zod, i18next, npm (ADR-021).
- Типы API генерируются из `contracts/openapi/*.json` (`npm run gen:api`). Ручной `fetch` запрещён. Токены — только в памяти. Моки (MSW) — только в dev.
- Весь интерфейс на русском. Каждый код отказа имеет человеческий текст и подсказку, что делать («Подойдите ближе к камере», «Обновите QR в телефоне»).
- У каждого экрана четыре состояния: загрузка, пусто, ошибка (с кнопкой «Повторить»), данные. Отдельно обрабатываем потерю сети.
- Киоск: полноэкранный режим, крупный шрифт, цвет и звук результата, автосброс за 3 с. Телефон: mobile-first, тач-цели от 48 px, PWA. Админка: desktop, таблицы с фильтрами.

## 5. Git
- Trunk-based: короткие ветки `feat/FR-12-token-consume`, мерж в `main` только через PR по зелёному CI. Ветка живёт меньше 2 часов.
- Conventional Commits: `feat(access): FR-12 атомарное гашение токена`. Коммиты маленькие и частые (история работы — часть оценки, Д7).
- Коммитит тот человек, кто писал с агентом, под своим именем, чтобы история показывала вклад каждого.
- Никаких `node_modules`, `build/`, `.gradle/`, `.venv/`, `.env`, моделей и фото в git.
- Каждые 2 часа тегаем стабильную точку `demo-N`, на которую можно откатиться перед защитой.

## 5.1 Работа агентов через PR
- Цикл и скрипты описаны в скилле `../.agents/skills/proxodnaya-dev/SKILL.md`: ID → ветка → `scripts/verify.sh` + `scripts/guard.sh` → `scripts/open-pr.sh`.
- Агент не мержит и не апрувит. Мерж делает человек-владелец (CODEOWNERS) после зелёного CI.
- Миграции — только через `scripts/new-migration.sh` (метка времени, ADR-012). Контракт — snapshot `contracts/openapi/<svc>.json` (`./gradlew :<svc>:exportOpenApi`, ADR-013).
- После clone: `scripts/install-hooks.sh` (pre-commit: gitleaks + guard).

## 6. Definition of Done для задачи
- [ ] Требование FR/NFR закрыто, ID указан в коммите
- [ ] Работает через интерфейс, а не только через curl (Д3)
- [ ] Ошибки внятные, коды из API.md
- [ ] Событие пишется в журнал/БД и переживает рестарт
- [ ] Тест или шаг в `scripts/smoke.sh`
- [ ] Владелец может объяснить код
- [ ] Документация/ADR обновлены, если поменялось поведение
