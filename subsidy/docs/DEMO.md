# Сценарий защиты — «Субсидии» (гипотеза до текста С1–С21, PLT-00)

Цель: за 7 минут показать все блоки баллов вживую на стенде, затем ответы владельцев модулей.

## 0. Подготовка (до выхода)
- Чистая БД (`docker compose down -v && up`), один демо-пользователь каждой роли; синтетические пакеты в `eval/synthetic/demo/` (вымышленные организации).
- Вкладки: рабочее место, Jaeger, терминал с `docker compose`, отчёт eval.

## 1. Закрытость (С16) — 20 с
Открыть `/specialist` и прямую ссылку на файл без входа → вход / 401. Войти специалистом.

## 2. Пакет «как в жизни» (С1–С4, 25 баллов) — 90 с
Создать пакет по ИНН, перетащить ZIP: файлы `1.pdf … 9.jpg`, перемешаны, одно расширение не то, один PDF содержит заявление + выписку + справку. Приём мгновенный, стадии идут вживую. Итог: каждый документ с видом и уверенностью, склейка разделена на три документа, посторонний файл — `OTHER`. Сказать: «имена файлов и порядок модель не видит — вот тест и `guard.sh`».

## 3. Комплектность (С5–С7, 15) — 40 с
Протокол: «не хватает платёжного поручения по счёту №…», условный пункт «доверенность не нужна — подписант = руководитель из ЕГРЮЛ». Дозагрузить платёжку → комплектность пересчитана.

## 4. Поля и правила (С8–С11, 20) — 90 с
Открыть счёт: оригинал слева, поля справа, клик по полю → подсветка на странице. Правило `SUM_INVOICE_ITEMS` FAILED: «сумма позиций 118 000,00 ≠ итог 120 000,00». `CROSS_INN`: ИНН в платёжке отличается. `SUM_SUBSIDY_CAP`: формула с числами. Поправить поле (ошибка OCR) → сервер перепроверил, новая версия протокола, запись в истории.

## 5. Смена типа и повторная загрузка (С14–С15) — 30 с
Документ с низкой уверенностью → сменить тип → поля переизвлечены. Заменить размытый скан → разобран заново.

## 6. Устойчивость и модель (С18–С19, 15) — 60 с
`docker compose restart docproc` посреди разбора → продолжил с той же стадии (Jaeger). `docker compose stop ollama` → `WAITING_MODEL`, не «проверено»; `start` → догнал. Бейдж «Ollama · qwen3:8b». Показать `.env`: `LLM_PROVIDER=ollama` ↔ `openai`. Таблица замера моделей.

## 7. Бонусы — 60 с
Выгрузка протокола DOCX; история организации; статистика частых ошибок; истекающие справки; помощник: «почему не прошла сумма субсидии?» → ответ с источниками и статусом валидатора.

## 8. Инженерия — 30 с
Схема архитектуры, DECISIONS, CI зелёный, eval-отчёт по 8 видам (честно: где ошибаемся).
