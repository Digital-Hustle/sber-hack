## 0. Подготовка (до выхода)
- Чистая БД (`docker compose down -v && up`), демо-пользователи `specialist` / `senior` / `auditor` (пароли — `KC_DEMO_*` в `infra/.env`).
- Пакеты вымышленных организаций генерируем заранее: `cd eval && uv run python -m synthetic.gen --out demo/ok --seed 7 --merged` (8 видов, склейка заявление+ЕГРЮЛ+справка в одном PDF, нейтральные имена `doc-XXXX.pdf`) и `--defect items --out demo/bad` (ошибка суммы сметы). Прогон стенда целиком: `EVAL_PASSWORD=… scripts/smoke.sh https://<host>`.
- Вкладки: рабочее место, Jaeger, терминал с `docker compose`, отчёт eval.

## 1. Закрытость (С16) — 20 с
Открыть `/specialist` и прямую ссылку на файл без входа → вход / 401. Войти специалистом.

## 2. Пакет «как в жизни» (С1–С4, 25 баллов) — 90 с
Создать пакет по ИНН, перетащить файлы из `demo/ok` (имена `doc-XXXX.pdf` ничего не говорят, порядок любой, один PDF — заявление + выписка ЕГРЮЛ + справка). Приём мгновенный, стадии идут вживую. Итог: каждый документ с видом и уверенностью, склейка разделена на три документа, посторонний файл — `OTHER`. Переключатель «Сомнительные сверху» поднимает документы на проверку; `J`/`K` — по документам, `1–3` — разделы. Сказать: «имена файлов и порядок модель не видит — вот тест и `guard.sh`».

## 3. Комплектность (С5–С7, 15) — 40 с
Протокол: «не хватает платёжного поручения по счёту №…», условный пункт «доверенность не нужна — подписант = руководитель из ЕГРЮЛ». Дозагрузить платёжку → комплектность пересчитана.

## 4. Поля и правила (С8–С11, 20) — 90 с
Открыть счёт: оригинал слева, поля справа, клик по полю → подсветка на странице. Правило `SUM_INVOICE_ITEMS` FAILED: «сумма позиций 118 000,00 ≠ итог 120 000,00». `CROSS_INN`: ИНН в платёжке отличается. `SUM_SUBSIDY_CAP`: формула с числами. Поправить поле (ошибка OCR) → сервер перепроверил, новая версия протокола, запись в истории.

## 5. Смена типа и повторная загрузка (С14–С15) — 30 с
Документ с низкой уверенностью → сменить тип → поля переизвлечены. Заменить размытый скан → разобран заново.

## 6. Устойчивость и модель (С18–С19, 15) — 60 с
`docker compose restart docproc` посреди разбора → продолжил с той же стадии (Jaeger). Если событие разбора потерялось, rules сам сверяет данные с docproc перед протоколом; вручную — кнопка «Сверить с разбором» (старший специалист). `docker compose stop ollama` → `WAITING_MODEL`, не «проверено»; `start` → догнал. Бейдж «Ollama · qwen3:8b». Показать `.env`: `LLM_PROVIDER=ollama` ↔ `openai`. Таблица замера моделей.

## 7. Бонусы (до +10, все 8 из Положения) — 60 с
Сверка между документами (`CROSS_INN`: ИНН заявления ≠ выписки); выгрузка протокола DOCX для заявителя; история организации; статистика частых ошибок; истекающие справки; помощник: «почему не прошла сумма субсидии?» → ответ с источниками, сам подсвечивает аномалии; неполный пакет — «чего не хватает и как дослать» в протоколе; уверенность типа по каждому файлу и «Сомнительные сверху».

## 8. Инженерия — 30 с
Схема архитектуры, DECISIONS, CI зелёный, eval-отчёт по 8 видам (честно: где ошибаемся).
